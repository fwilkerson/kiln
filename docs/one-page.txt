::: titleblock
cell id | One developer, one Mac, many agents
wordmark kiln
motto Tooling in. Commits out.
para kiln runs Claude Code in the background, on your Mac. Features land from the specs you approve, and chores get done on a schedule, so one developer keeps a whole repository moving.

cell problem | How agents get used
lead **You take each task to an agent.**
para You bring it the work, watch it go, check what it did, and bring the next.
para What if you built the system instead, and the agents got the work done inside it?

cell answer | With kiln
big You shape the @you{specs} and build the tooling; kiln puts the @agent{agents} to work within it.
para **Specs become commits.** One session writes the code, another the tests from the spec alone. What passes your checks and an audit lands on main.
para **Your checks decide.** kiln reads them from main, so no build can weaken them.
para **kiln runs on itself.** Its monitors fix filed bugs with a test that fails first, refactor the lowest-scoring files, correct stale docs, and speed up a slowing gate.

cell attn | Where your time goes
item ●1 | **Ideas**: what to build next, shaped into a spec with `/shape`.
item ●2 | **The system**: the gate, the monitors and the agents' instructions that every build runs within.
item ●3 | **The product**: try what landed, and decide what comes next.
:::

box shape @you 1.1 | **shape a spec** ●1 | `/shape`, then approve
more `/shape` asks what it needs, and the project's reviewers read the draft before you approve it. Its acceptance tests say what done means, each a Given, a When and a Then.
box queue @you 1.2 | `kiln queue x` | `kiln fire`
box spec @repo 1.1-2 | 📄 SPEC | approved, on main
arrow shape spec

box build @agent 2.1 | BUILD | the code
box verify @agent 2.1 | VERIFY | the tests, from | the spec alone
more Two sessions, in two clones: one writes the code, the other the acceptance tests. Neither reads the other's work.
box gate @kiln 2.2 | GATE ●2 | your checks, | read from main
more kiln reads the gate's commands from main, never from the build's checkout, so a build cannot weaken the checks it is held to.
box audit @agent 2.3 | AUDIT | a second session | reads the work
more A failing gate, or the audit's findings, go back to the build as a round. Detail A says what happens when rounds run out.
arrow queue build
arrow queue verify
arrow build gate
arrow verify gate
arrow gate audit
detail A | build gate audit

box land @kiln 3.1 | LAND | one commit
box main @repo 3.1 | MAIN
box try @you 3.2 | **try it** ●3 | `kiln accept x`
arrow audit land
arrow land main
arrow main try
:::

::: details
detail A | Detail A — when a build cannot land as it is | It keeps its checkout, so you can ask its session why.
rung @agent | 1 · Round | the build | A failing gate, or the audit's findings, go back to the session, up to three times.
rung @agent | 2 · Amend | the build | A spec found wrong gets an amendment, and the build waits on its branch.
rung @you | 3 · Decide | you ●3 | Accept or reject the amendment, or fix the spec and queue it again.
:::

view 3 AUTOMATE | what monitors and gauges could do | four kiln runs on its own repository, as examples

::: assembly
box launchd @kiln A2-A3 | LAUNCHD | `kiln monitor run`, | each hour
group monitors B1-B4 | MONITORS, FOR EXAMPLE ●2
box bugs @kiln B1 | BUGS {1} | every hour
box health @kiln B2 | CODE HEALTH {2} | every day
box gate-time @kiln B3 | GATE TIME {3} | every day
box docs @kiln B4 | DOCS {4} | every day
box fix @agent C2-C3 | A FIX {5} | a session with | the monitor's | own agent
valve gate @kiln | GATE
rail main @repo D1-D4 | MAIN
arrow launchd monitors
arrow monitors fix
arrow fix main via gate

parts PARTS LIST | a check or a gauge on a schedule, then an agent's fix
part 1 @kiln | Bugs | a check lists `bugs/`; its fix takes the first report | Fixes each bug you file, one after another, with a test that fails first.
part 2 @kiln | Code health | a gauge scores changed files | Refactors the three lowest-scoring files, and changes no behavior.
part 3 @kiln | Gate time | a check compares the gate's recent times with the times before | Once the gate slows by half, speeds up the slowest tests without weakening one, and waits for you.
part 4 @kiln | Docs | a check finds packages whose code changed | Reads their docs against the code, fixes what is false, and waits for you.
part 5 @agent | A fix | a build with no spec | Gated, audited and landed like any build.
:::

::: spec
column
howto 4.1 | Set a project up | `kiln init` @you
```term
$ kiln init
wrote .kiln/kiln.json
linked .claude/skills/shape
{q:commit .kiln/ on main: kiln reads it there}
```
caption The preset is `go`, or `python` for uv, pytest, ruff and ty.
column
howto 4.2 | Build a spec | `kiln queue answer` @you then `kiln fire` @you
```term
$ kiln fire
answer: {ok:landed on main} at {h:3f9c2ab81d0e}
  4.2 min · $0.42 · 3 turns
  next: kiln accept answer
```
caption `kiln tui` shows each session live.
column
howto 4.3 | Add a monitor | `kiln monitor install` @you
```term
$ .kiln/monitors/bugs
# A gate command that leaves a child behind …
\{"fix": true, "summary": "18 in bugs/, …"}
```
caption A check is any script whose last line says whether a fix is due. Name it, an agent and a schedule in `kiln.json`.
:::
